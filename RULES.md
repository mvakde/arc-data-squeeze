# Rules

Version 1, 10 November 2026. Rules change only by a pull request that bumps this version. Records keep the
version they were set under.

## 1. Data

You may train only on the files `prepare_data.py` builds for your tier and benchmark. The build pins every
source to a commit and checks every output against [`data/MANIFEST.json`](data/MANIFEST.json).

| Tier | Data |
| --- | --- |
| **ARC-only** | ARC-AGI-1 (800 tasks) and ARC-AGI-2 (1,120 tasks), deduplicated by task ID |
| **Main** | ARC-only plus ConceptARC (160 tasks) |
| **+ReARC** | Main plus the pre-generated ReARC examples in the pinned `re_arc.zip`: up to 1,000 per ARC-AGI-1 training task, 129 known-bad pairs removed |

- You can use any subset of the data, in any order, with any weighting.
- **Generic augmentation is allowed.** That means transforms that treat every task alike: rotations, reflections,
  transposes, colour permutations, scaling, re-pairing demos. Transforms written for particular tasks are not.
- **Nothing else is allowed:** no other ARC-like data (BARC, NVARC, RE-ARC generators run again, Mini-ARC, etc.),
  no puzzles written or generated by people or programs, and no text, code or image corpora.
- An entry belongs to the tier of the data it used. A method that needs less data may also be listed in a higher
  tier.

## 2. The transductive protocol

ARC-AGI-1 and ARC-AGI-2 are scored on their public evaluation sets: 400 tasks with 419 test inputs, and 120 tasks
with 167 test inputs.

- **Allowed:** the evaluated tasks' demo pairs, in training and at test time; their test inputs, at test time,
  for anything (test-time training, search, self-consistency).
- **Never allowed:** their test outputs. They are used only by `score.py`. They never enter training, tuning,
  test-time training or decoding.
- **No selecting by eval score:** you may not pick a checkpoint, seed or ensemble member by its eval score. Report
  every seed you ran with the final recipe. Comparing recipes on the public eval while you develop one is normal
  practice, and is why reruns with new seeds matter.
- **Shared task IDs:** the withheld outputs stay withheld wherever the same task ID appears. ARC-AGI-2's training
  set contains 376 of the 400 ARC-AGI-1 evaluation tasks, and `prepare_data.py` removes them from the ARC-AGI-1
  build.

## 3. One model per benchmark, from scratch

- Train from random initialisation, separately for each benchmark, on that benchmark's build.
- Every learned value must come from that build. An ARC-AGI-1 entry cannot start from a model trained on the
  ARC-AGI-2 build, because that build contains ARC-AGI-1 evaluation answers.
- Use the same method for both benchmarks. Benchmark-specific settings such as epochs or batch size are fine if
  you list them.

## 4. Models and code

- **LLMs and pretrained models are forbidden** at every stage: no pretrained weights or embeddings, no
  distillation, no generated data, no LLM calls at test time.
- **You may use them as coding assistants** for writing your training code.
- **Hand-written, task-agnostic components are allowed if you declare them.** Examples: a DSL, program search,
  symbolic checks of a candidate.
- **Rules written for particular tasks or task families are forbidden**, as are any lookup of known answers.

## 5. Compute and parameters

- Compute is unlimited. Report the hardware and the GPU-hours for training and for decoding, per run.
- **Parameters:** every learned value used at inference, counted once. This includes per-task or per-puzzle
  embeddings learned in training, and every member of an ensemble. Weights updated at test time count once.

## 6. Scoring

- **Top-2**, the official ARC Prize metric, is the ranked score. Each test input gets two attempts. A task scores
  the fraction of its test inputs that either attempt gets exactly right. The result is the mean over tasks, in
  percent.
- **Oracle** is reported, never ranked. It is the same aggregate, counting a test input as solved if the answer is
  among your first 100 distinct candidates. Without a candidates file there is no oracle.
- `score.py` is the reference implementation. A row's score per benchmark is the mean over its reported seeds.

## 7. Records

- A record entry beats its tier's current best top-2 on ARC-AGI-1 or on ARC-AGI-2. There is no combined score.
- Records need public code at a commit, the exact command, the predictions for every seed, and the weights for at
  least one seed.
- One seed is accepted, and the tables show how many seeds each row has. A record set with fewer than 3 seeds
  should win by more than the noise (see the FAQ). Three seeds make it solid.
- Maintainers re-score every record and re-run top entries when they can. Anyone can challenge an entry in an
  issue. An entry that cannot be reproduced is removed.
