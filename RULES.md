# Rules

Version 1, 11 November 2026. Rules change only by a pull request that bumps this version. Records keep the
version they were set under.

## 1. Data

- **Train only on the files `prepare_data.py` builds:** ARC-AGI-1 (800 tasks) and ARC-AGI-2 (1,120 tasks),
  deduplicated by task ID, plus ConceptARC (160 tasks), 1,307 tasks per benchmark. The build pins every source to a
  commit and checks every output against [`data/MANIFEST.json`](data/MANIFEST.json).
- You can use any subset of the data, in any order, with any weighting.
- **Nothing else:** no other ARC-like data (ReARC, BARC, NVARC, Mini-ARC, etc.), no puzzles written or generated by
  people or programs, and no text, code or image corpora.
- **Harder tracks follow progress.** When an entry passes 90% top-2 on ARC-AGI-1, a track without ConceptARC opens.
  When that track passes 90%, a track with only each benchmark's official tasks opens: for ARC-AGI-1, its 800 tasks
  and no ARC-AGI-2 tasks.

## 2. Inductive biases

Any learned component is allowed: any architecture, objective, optimiser or test-time training. What the rules limit
is knowledge about ARC that you write by hand.

**The principle.** A model may be told what a person sees when first shown an ARC task. Anything a person would have
to work out from the grids' contents, the model must learn from the data.

**Allowed**, because a person sees it:

1. **Grid layout:** each cell's row and column, which grid it belongs to (demo input or output, test input or
   output), which input goes with which output, and which grid is the question. Any encoding of this is fine: tokens,
   positional encodings, attention masks. Hub-and-spoke attention, where each demo attends within itself and to the
   test input, only encodes which grid is which, so it is allowed.
2. **Views that keep the puzzle:** the 8 rotations and reflections and colour permutations, applied to the whole
   task, and any order or subset of the demos. Turning the page or using a mirror gives the same puzzle, and a person
   is told that the colours carry no meaning outside the puzzle. They may be used as training augmentation and as
   test-time views.
3. **Checking an answer by looking again:** undoing those views and voting, and ranking candidates by the model's own
   scores.

**Examples of what is not allowed**, because a person would infer it from the contents:

- other augmentations: scaling, translation, cropping, padding, tiling. They change the contents (an upscale turns
  "move one cell" into "move two cells"), so assuming that rules survive them is knowledge about ARC;
- features computed by hand from cell colours: objects, connected components, symmetries, counts;
- checks or filters on candidate answers, such as deterministic filters that reject outputs whose colours or size
  contradict the demos;
- DSLs, program search, symbolic solvers.

**Borderline cases** are decided by the maintainer with the same test: would a person know this before working
anything out from the grids? Ask in an issue before building on a component you are unsure about. Decisions are added
to this section.

Rules written for particular tasks or task families are never allowed, nor is any lookup of known answers, even in
the Open table.

## 3. The transductive protocol

ARC-AGI-1 and ARC-AGI-2 are scored on their public evaluation sets: 400 tasks with 419 test inputs, and 120 tasks
with 167 test inputs.

- **Allowed:** the evaluated tasks' demo pairs, in training and at test time; their test inputs, at test time,
  for anything (test-time training, search, self-consistency).
- **Never allowed:** their test outputs. They are used only by `score.py`. They never enter training, tuning,
  test-time training or decoding.
- **No selecting by eval score:** you may not pick a checkpoint, seed or ensemble member by its eval score. Report
  every seed you ran with the final recipe. Comparing recipes on the public eval while you develop one is normal
  practice, and is why reruns with new seeds matter.
- **Shared task IDs:** the withheld outputs stay withheld wherever the same task ID appears. ARC-AGI-2's training
  set contains 376 of the 400 ARC-AGI-1 evaluation tasks, and `prepare_data.py` removes them from the ARC-AGI-1
  build.

## 4. One model per benchmark, from scratch

- Train from random initialisation, separately for each benchmark, on that benchmark's build.
- Every learned value must come from that build. An ARC-AGI-1 entry cannot start from a model trained on the
  ARC-AGI-2 build, because that build contains ARC-AGI-1 evaluation answers.
- Use the same method for both benchmarks. Benchmark-specific settings such as epochs or batch size are fine if
  you list them.

## 5. No LLMs or pretrained models

LLMs and pretrained models are forbidden at every stage: no pretrained weights or embeddings, no distillation, no
generated data, no LLM calls at test time. You may use them as coding assistants for writing your code.

## 6. Compute and parameters

- Compute is unlimited. Report the hardware and the GPU-hours for training and for decoding, per run.
- **Parameters:** every learned value used at inference, counted once. This includes per-task or per-puzzle
  embeddings learned in training, and every member of an ensemble. Weights updated at test time count once.

## 7. Scoring

- **Top-2**, the official ARC Prize metric, is the ranked score. Each test input gets two attempts. A task scores
  the fraction of its test inputs that either attempt gets exactly right. The result is the mean over tasks, in
  percent.
- **Oracle** is reported, never ranked. It is the same aggregate, counting a test input as solved if the answer is
  among your first 100 distinct candidates. Without a candidates file there is no oracle.
- `score.py` is the reference implementation. A row's score per benchmark is the mean over its reported seeds.

## 8. Records

- A record entry beats the best top-2 on ARC-AGI-1 or on ARC-AGI-2. There is no combined score.
- Records need public code at a commit, the exact command, the predictions for every seed, and the weights for at
  least one seed.
- One seed is accepted, and the tables show how many seeds each row has. A record set with fewer than 3 seeds
  should win by more than the noise (see the FAQ). Three seeds make it solid.
- Maintainers re-score every record and re-run top entries when they can. Anyone can challenge an entry in an
  issue. An entry that cannot be reproduced is removed.

## 9. The Open table

Interesting results that break sections 1 or 2, for example with extra data or hand-written knowledge, can be listed
in the README's Open table. They are not records. Submit them under `records/open/` like any entry, and list every
data source and hand-written component beyond these rules in `declared_components`. Sections 3 to 5 still apply:
no evaluation test outputs, separate models per benchmark trained from scratch, and no LLMs or pretrained models.
